📖 什么是 vv-switch？

vv-switch 是一个轻量级 LLM API 协议转换代理，运行在本地（默认 http://localhost:4321），作为 Claude Code、OpenAI Codex 以及任意 OpenAI Chat Completions 客户端（如 VS Code Copilot 自定义端点）与各类 LLM 提供商之间的中间层。

通过协议转换，你可以使用 DeepSeek、阿里百炼（DashScope）、智谱等任何支持 OpenAI Chat Completions、Anthropic Messages 或原生 Responses API 的提供商来驱动 Claude Code、Codex 和 VS Code Copilot 等客户端。

🔌 支持的客户端协议

客户端入口协议转换目标
Claude Code/v1/messages (Anthropic Messages)Chat Completions / Anthropic 兼容端点
OpenAI Codex/v1/responses (Responses API)Chat Completions / 原生 Responses API
OpenAI 端点 (VS Code Copilot 等)/v1/chat/completionsChat Completions / Anthropic 兼容端点

⚙️ 快速使用

  1. 添加供应商 — 在「供应商管理」Tab 中添加 LLM 提供商（名称、API 地址、API Key、模型、协议类型）
  2. 测试连接 — 填写完成后点击「测试连接」验证配置是否正确
  3. 应用配置 — 切换到「应用配置」Tab，为 Claude Code / Codex / OpenAI 端点分别选择要使用的供应商
  4. 开始使用 — 正常使用 claude 或 codex 命令即可；VS Code Copilot 等指向 http://localhost:4321/v1
  5. 停止服务 — 按 Ctrl+C 停止，自动还原原始配置

🧩 支持的协议类型

协议类型上游端点认证方式适用场景
chat/chat/completionsAuthorization: BearerDeepSeek、DashScope /v1、OpenAI 等
anthropic/v1/messagesx-api-keyDashScope /apps/anthropic、智谱等
responses/v1/responsesAuthorization: Bearer原生 Responses API 兼容提供商
ollama/api/chat无需 / 可选 Bearer本地 Ollama 服务

🛠️ 主要功能

  • 协议转换 — Responsess API ↔ Chat Completions、Anthropic Messages ↔ Chat Completions，以及 Anthropic 直传、Responses 直传
  • 流式支持（SSE） — 全链路 SSE 流式支持，双向协议转换
  • 工具调用（Tool Calling） — 多轮工具对话完整支持，各协议间正确映射
  • 能力探测 — 自动检测上游 LLM 提供商的能力，并据此决定是否启用降级方案
  • 中间件管道 — 洋葱模型的请求处理：鉴权、日志、指标、重试、限流、能力检查
  • Prompt Rules 规则管理 — 通过正则规则动态修改请求中的消息内容
  • 供应商管理 — 通过 Web UI 管理多个 LLM 提供商配置，独立设置 Claude / Codex / OpenAI 端点活跃供应商
  • 配置注入与自动还原 — 应用配置时自动写入 Claude/Codex 配置，停止服务时自动还原
  • 日志与可视化 — JSONL 格式日志，内置 HTML 日志查看器，支持会话列表、搜索过滤、JSON/Table 视图
  • 协议日志 — 面向协议转换排查的四阶段链路日志（ingress → standard → upstream → egress）

💻 CLI 用法

npx vv-switch [options] 选项: -p, --port <port> 监听端口（默认 4321） -h, --host <host> 监听地址（默认 localhost） --debug 开启调试日志 --logs 开启日志记录与可视化 --logs-dir <dir> 自定义日志目录路径 --no-body 不捕获请求/响应体（只记摘要） --protocol-log 开启协议转换链路日志 --protocol-log-dir <dir> 自定义协议日志目录（默认 ./log）
